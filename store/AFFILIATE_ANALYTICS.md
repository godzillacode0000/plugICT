# PlugICT Affiliate Analytics

## Current Gate B implementation

Gate B adds a Cloudflare Pages Functions + D1 preview data plane while keeping the current GitHub Pages host and the private SQLite ledger unchanged.

- `functions/api/health.js` — non-sensitive health marker.
- `functions/api/affiliate/click.js` — public, deduplicated click ingestion.
- `functions/api/affiliate/stats.js` — private aggregate stats for one authenticated affiliate.
- `cloudflare/schema.sql` — analytics-only D1 schema.
- `cloudflare/retention-worker/src/index.js` — scheduled 90-day click cleanup.
- `scripts/sync_affiliate_to_d1.py` — fail-closed local-ledger-to-preview-D1 mirror.
- `assets/affiliate-analytics.js` — fresh-ref-only beacon; production API config remains empty.
- `affiliate-dashboard.html` — session-only token input and honest finance-null rendering.

The previous `store/affiliate_portal.py` remains a local compatibility/prototype service. It is not the Gate B production authority and must not be started as a public service without a separate review.

## Data boundaries

D1 stores only:

- affiliate code, display name, status, and SHA-256 token hash;
- click ID, affiliate code, HMAC visitor hash, landing path, referrer hostname, day, and created timestamp.

D1 does not store buyer email, raw IP, raw user-agent, raw visitor ID, Stripe IDs, payment amounts, commission values, payout state, license data, or secrets. Stripe and the local SQLite ledger remain the financial authority. D1 click counts are operational analytics and never payout proof.

## Referral semantics

A click is sent only when a visitor lands with a fresh valid `?ref=CODE`. A stored referral in localStorage remains available for checkout attribution but does not generate a new click on later visits. The beacon uses `fetch()` with `keepalive` and `text/plain;charset=UTF-8`; `navigator.sendBeacon(application/json)` is intentionally not used.

## Token handling

Affiliate tokens are generated by the private ledger and stored as SHA-256 hashes. The dashboard accepts a token only from a password field and keeps it in `sessionStorage`. Query-string token bootstrapping is removed. Token hashes are mirrored to preview D1 by `scripts/sync_affiliate_to_d1.py`; raw tokens are never placed in SQL, HTML, committed config, or public URLs.

## Retention

Click rows older than 90 days are deleted by the bounded scheduled Worker. Each invocation deletes at most five batches of 1,000 rows. The Worker touches only `affiliate_clicks` and has no public maintenance endpoint.

## Finance status

The dashboard may show click and approximate-visitor counts. Purchases, conversion rate, pending commission, paid commission, and voided purchases remain `Not connected`/`null` until an authoritative read-only financial synchronization is separately designed and approved. Missing finance data must never be represented as zero.

## General analytics

Cloudflare Web Analytics is the intended provider-native general traffic analytics layer for a later activation gate. Gate B does not enable it and does not add a custom pageview table. When enabled, the privacy page must describe the provider and reporting behavior.

## Validation before any production activation

1. Run `npm test` and the existing Python affiliate regression tests.
2. Apply `cloudflare/schema.sql` to local D1.
3. Run the Functions preview with test affiliate rows/tokens only.
4. Verify fresh referral = one click, stored referral reload = no new click.
5. Verify one affiliate cannot query another affiliate's stats.
6. Verify analytics outage does not affect static page or checkout behavior.
7. Verify dashboard finance fields remain unavailable.
8. Keep `assets/affiliate-config.js` empty until hosting/API and controlled attribution tests are complete.
